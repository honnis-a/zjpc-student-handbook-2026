# 浙江药科职业大学学生手册（2026 版）开源 md 文件

将纸质学生手册整理为可阅读、搜索和供 AI 检索的 Markdown 文件，方便同学们复习和查找原文。

## 项目创建初衷

**为了应付考试。**

纸质手册翻找起来不方便，所以把它数字化：需要查规定时直接搜索，也可以把文件交给 AI 辅助复习，减少来回翻书的时间。

## 项目内容

| 文件 | 用途 |
| --- | --- |
| [学生手册.md](output/学生手册.md) | 手册正文，复习和检索主要使用这个文件 |
| [页码对照.csv](output/页码对照.csv) | 对照整理后的页面序号、书本印刷页码和来源图片 |
| [需要重新上传的页面.md](output/需要重新上传的页面.md) | 记录尚未识别清楚或缺失的页面，便于补拍 |

当前版本覆盖印刷第 **1–158 页**。空白页和原扫描中的重复页均保留记录，重复页带有提示；目前没有待补传页面。

## 使用方法

### 直接阅读和搜索

打开 [学生手册.md](output/学生手册.md)，可以直接在 GitHub 阅读，也可以下载后使用 Markdown 阅读器或文本编辑器打开。使用 `Ctrl + F`（Windows）或 `Command + F`（macOS）搜索关键词，例如“奖学金”“转专业”“违纪处分”。

### 配合 AI 复习

将 `学生手册.md` 上传到支持读取 Markdown 文件的 AI 工具中，再按章节提问、查找条款或生成复习题。可以这样提问：

> 请仅依据这份学生手册回答，引用对应原文并标注书本印刷页码；找不到依据时请明确说明，不要自行补充。

### 定位原书页面

正文中的页面标记示例：

```md
<!-- Page: 167 | Book Page: 158 | Source: IMG_20261016_074036.jpg | Side: 单页 -->
```

- `Page`：整理文件中的页面序号。
- `Book Page`：原书印刷页码，查书时以此为准。
- `Source`：来源图片文件名。
- `Side`：该页来自单页照片，还是双页照片的左页或右页。
- `Blank: true`：已核对的空白页。

## 项目创建流程

本项目的 Markdown 整理与本 README **由 GPT-6.1 sol Ultra 生成**。

供以后整理新版手册的同学参考：

1. **拍摄或扫描原书。** 保留完整页面和印刷页码，注意书脊阴影、失焦及边缘裁切。
2. **清点页面。** 核对图片与印刷页码，记录缺页、空白页和重复拍摄；双页照片分别登记左右页。
3. **进行 OCR。** 本次使用 Python 调用 macOS Vision 做本地文字识别，关闭语言纠错，再借助 AI 对照原图逐页核对。
4. **整理 Markdown。** 合并原书换行造成的断行，恢复自然段和标题层级，保留条款编号、数字、标点及原文表述，不总结、不改写、不润色。
5. **标记疑点并补拍。** 区分正面正文与背面透印。无法确认的字词、数字和标点明确标注页码，列入补传清单；根据重新拍摄的图片修正，不能靠上下文猜测。
6. **合并并检查。** 为每页加入定位标记，核对有无漏页、段落错序或编号错误，保留原扫描重复页，更新页码对照表和补传清单。

本次使用的辅助脚本保存在 [tools/](tools/) 中，依赖 macOS Vision、Python、Pillow、本机文件路径及部分处理中间文件，可作为流程参考。复用前需要按自己的目录、输入文件和系统调整。

整理时遵循：**准确性高于完整性，完整性高于美观。** 原图明确显示的错别字或异常编号也按原书保留。

```text
你现在是一名专业的 OCR 书籍数字化整理助手。

我会上传一本“纯文本学生手册”的扫描 PDF 或扫描图片。你的任务是把它忠实转换成 Markdown 文件，方便后续 AI 阅读、搜索和检索。

这本书基本只有文字，没有复杂图片、表格或公式，因此请重点保证文字识别准确。

请严格遵守以下要求：

1. 绝对忠实于原文

- 不允许总结。
- 不允许改写。
- 不允许润色。
- 不允许删减。
- 不允许根据上下文补全内容。
- 不允许因为一句话“看起来应该是这样”就自行猜测。

你的任务只是把扫描件中的原文准确转换成 Markdown。

2. 看不清时绝对不要猜

这是最重要的要求。

如果某一页存在以下情况：

- 页面模糊
- 字体过小
- 扫描失焦
- 页面缺角
- 阴影遮挡
- 文字被裁切
- 无法确认某些字词
- OCR 结果存在明显歧义

请不要自行推测原文。

只要你不能高置信度确认原文，就必须记录该页存在问题。

例如：

`[第 37 页识别不清，需要重新上传]`

如果只是局部看不清，也请明确指出：

`[第 37 页第 3 段部分文字识别不清，需要重新上传]`

不要使用上下文猜测缺失文字。

3. 每批处理完成后，必须单独列出所有识别有问题的页面

输出正文完成后，再增加：

## 需要重新上传的页面

例如：

- 第 17 页：右下角文字模糊
- 第 38 页：整页失焦
- 第 52 页：最后一段被裁切
- 第 67 页：有两个词无法确认

如果所有页面都清晰，则写：

`本批次所有页面均可清晰识别。`

我会根据这个列表重新上传有问题的页面。

4. 保留页码

每一页开始前加入：

`<!-- Page: 001 -->`

例如：

`<!-- Page: 025 -->`

这样以后能够根据 Markdown 内容重新定位到原书扫描页。

如果书本自身有印刷页码，同时 PDF 页码和印刷页码不同，可以写：

`<!-- PDF Page: 31 | Book Page: 27 -->`

5. 页面不能遗漏

必须按照原扫描文件顺序逐页处理。

每处理一页，都必须有对应的 Page 标记。

例如：

`<!-- Page: 001 -->`

正文……

`<!-- Page: 002 -->`

正文……

禁止因为页面内容相似而自动跳过。

禁止自行判断某一页“不重要”而忽略。

6. 处理重复页

如果扫描文件中真的出现重复页面，不要擅自删除。

请标记：

`[疑似与第 XX 页重复，请人工确认]`

然后仍然保留该页内容。

7. 正文段落

请恢复正常中文段落。

扫描 OCR 经常会因为原书换行而把一句话拆成很多行。

请把属于同一个自然段的内容重新合并成正常段落。

但是：

- 不要合并不同段落。
- 不要改变原文语序。
- 不要修改作者的表达方式。

8. 标题结构

根据原书排版识别标题，并使用 Markdown：

`# 书名`

`## 一级标题`

`### 二级标题`

`#### 三级标题`

如果不能确定某段文字是不是标题，优先忠实保留原样，不要自行创造标题层级。

9. 页眉和页脚

如果每页都有重复出现的：

- 书名
- 学校名称
- 章节名称
- 页码

可以删除重复页眉页脚。

但正文中的任何内容都不得删除。

页码通过：

`<!-- Page: XXX -->`

进行保留。

10. 标点和数字必须准确

特别检查：

- 年份
- 日期
- 电话号码
- 学号相关格式
- 条款编号
- 数字
- 百分比
- 中英文标点
- 大小写字母

学生手册中可能包含大量规章制度，因此数字和编号尤其不能猜。

例如：

“第三十二条”

不能因为 OCR 不清晰自行判断是“第三十三条”。

无法确认就标记为识别不清。

11. 条款结构必须保留

如果原书使用：

第一章

第一条

（一）

1. \


（1）

等编号结构，请完整保留。

不要重新编号，也不要自行调整编号顺序。

如果发现原书本身编号异常，也按原书保留。

12. 错别字处理原则

如果扫描原图明确显示原书就是这样写的，即使你认为原文存在错别字，也不要修改。

OCR 识别错误只有在能够通过原扫描图片明确确认时才能修正。

不允许根据常识自动纠错。

13. Markdown 输出要求

最终输出应该干净、简洁。

不要加入：

“以下是 OCR 结果”

“我已经完成整理”

“根据图片可以看到”

“这一页主要讲了……”

等 AI 自己的解释。

Markdown 正文中只保留：

- 原书文字
- 标题结构
- 页码标记
- 必要的识别异常标记

14. 分批处理

如果文件页数很多，不要为了完成任务而压缩、概括或者跳页。

每次只处理我指定的页面范围。

例如我说：

“处理第 1–30 页”

你就只处理第 1–30 页。

处理完成后停止。

不要继续处理第 31 页之后的内容。

15. 质量检查

每批完成后，请检查：

- 是否每一页都有 Page 标记
- 是否有漏页
- 是否出现重复页
- 是否有明显错字
- 是否有条款编号识别错误
- 是否有段落顺序错误
- 是否存在看不清却自行猜测的内容

如果不能确定，宁可标记“需要重新上传”，也不要猜测。

16. 最高原则

准确性高于完整性，完整性高于美观。

看不清就明确告诉我页码。

不要猜。\
不要脑补。\
不要根据上下文补字。\
不要为了让句子通顺而修改原文。

如果某一页无法可靠识别，请直接告诉我：

`第 XX 页需要重新上传。`

我会重新扫描并上传该页面。
```
